# Аутентификация и авторизация в Laravel

Аутентификация устанавливает личность пользователя, а авторизация определяет разрешённые ему действия. Обе задачи относятся к устройству продукта в целом, а не только к экрану входа.

## Начните с официального стартового набора

Создавая приложение командой `laravel new`, выберите стартовый набор, подходящий будущему интерфейсу. Официальные наборы дают основу для входа, регистрации, сброса пароля, подтверждения электронной почты и настроек учётной записи.

После настройки базы данных выполните:

```bash
php artisan migrate
composer run dev
```

Проверьте весь путь: регистрацию, вход, выход, сброс пароля и подтверждение электронной почты. В рабочей среде для почтовых сценариев нужны настроенный `MAIL_MAILER` и доступный для проверки почтовый ящик.

## Защита закрытых маршрутов

Объедините маршруты, которым нужен аутентифицированный сеанс. Добавьте `verified`, если действие разрешено только после подтверждения электронной почты:

```php
use App\Http\Controllers\ProjectController;
use Illuminate\Support\Facades\Route;

Route::middleware(['auth', 'verified'])->group(function () {
    Route::resource('projects', ProjectController::class);
});
```

Промежуточный обработчик решает, можно ли войти в раздел; политика определяет, можно ли выполнить действие с конкретной записью.

## Политики для правил предметной области

Создайте политику для записей, принадлежащих организации, команде или пользователю:

```bash
php artisan make:policy ProjectPolicy --model=Project
```

В политике проверяйте реальную связь пользователя с записью: организацию, роль или владение. Никогда не доверяйте идентификаторам из браузера без подтверждения, что они принадлежат вошедшему пользователю.

## Проверки перед выпуском

- Требуйте надёжные пароли и никогда не записывайте пароли или токены в журналы.
- Сохраняйте ограничение частоты запросов на вход и восстановление доступа.
- Включайте подтверждение электронной почты для сценариев, которым нужна проверенная личность.
- Проверяйте разрешения административных ресурсов через тестовую учётную запись без привилегий.
- Настройте HTTPS, защищённые файлы cookie и переменные окружения вне репозитория.
