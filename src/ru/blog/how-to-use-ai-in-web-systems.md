# Как использовать ИИ в веб-системах

Языковая модель полезна продукту только тогда, когда задача ясна, ответ можно проверить, а вызов идёт через ваш сервер. Иначе чат превращается в расходы, риск утечки данных и сервис, который трудно объяснить клиенту.

## Сначала опишите задачу, потом выбирайте модель

В веб-системе ИИ лучше справляется с повторяемой работой: классификация заявки, извлечение полей из текста, краткое изложение разговора, подсказка следующего шага или заполнение JSON по правилам. Если нельзя записать пример входа, ожидаемый выход и критерий ошибки, функция ещё не готова к публикации.

Отдельно зафиксируйте, чего модель делать не должна. Расчёт цены, права пользователя, склад, договор и любые решения с единственным источником истины остаются в коде и в базе данных.

## Вызывайте модель с сервера

Ключ API, текст подсказки и история разговора не должны попадать в браузер. В Laravel вынесите интеграцию в сервис и читайте секрет из окружения:

```php
use Illuminate\Support\Facades\Http;

class LanguageModel
{
    public function complete(string $system, string $user): array
    {
        $response = Http::withToken(config('services.openai.key'))
            ->timeout(30)
            ->post('https://api.openai.com/v1/chat/completions', [
                'model' => config('services.openai.model', 'gpt-4o-mini'),
                'temperature' => 0.2,
                'response_format' => ['type' => 'json_object'],
                'messages' => [
                    ['role' => 'system', 'content' => $system],
                    ['role' => 'user', 'content' => $user],
                ],
            ]);

        $response->throw();

        return json_decode($response->json('choices.0.message.content'), true, 512, JSON_THROW_ON_ERROR);
    }
}
```

Тот же контракт подходит для поставщиков, совместимых с OpenAI. Смена модели становится настройкой, а не переписыванием страницы.

## Требуйте структурированный ответ

Запрашивайте JSON с именованными полями и отклоняйте данные, если нет нужного ключа, типа или допустимого значения. Так результат можно сохранить, показать ошибку и сравнить версии подсказки.

Короткий системный запрос обычно стабильнее длинного и расплывчатого. Укажите роль, формат, что игнорировать и минимальный пример. Храните подсказку в репозитории, чтобы у вчерашнего поведения была история.

## Защитите данные, стоимость и сбои

Не отправляйте целиком документ, пароль, медицинскую карту или персональные данные, если достаточно фрагмента. Ограничьте частоту запросов на пользователя, число токенов, время ожидания и предусмотрите запасной путь: очередь повторов, сообщение человеку или детерминированное правило.

Записывайте модель, токены, задержку, версию подсказки и результат проверки. Без этого нельзя понять, дорог ли ИИ, медлителен ли он или выдумывает факты.

Если решение касается денег, здоровья, юридических вопросов или удаления данных, оставьте человека в цепочке. Закон о защите данных по-прежнему действует: модель — обработчик, а не повод раскрывать контекст.

## Контрольный список перед публикацией

- У задачи есть записанные вход, выход и критерий качества.
- Ключ API хранится только на сервере, с тайм-аутом и ограничением частоты.
- Ответ проходит через схему; некорректные данные не выдаются пользователю как истина.
- Журналы показывают стоимость и сбой без чувствительных сведений.
- Есть запасной путь, если поставщик недоступен или качество падает ниже порога.
